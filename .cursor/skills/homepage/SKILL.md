# Homepage

Write for the end-user developer. Buyer/ROI on separate pages.

Framework: [references/sections.md](references/sections.md).

## Process

From repo root: `node scripts/run-state-check.js homepage`.

Requires **Positioning bet** and **ICP hypothesis**.

1. Audit current hero: what it is, for whom, in 5 seconds?
2. Draft section order: hook → hero CTAs → social proof → differentiation → getting started.
3. Cross-check Frankl six (problem language, villain, proof, urgency, social proof, low-friction try).
4. Run `review`, then `write` on customer-facing copy blocks.

## Output

- Section outline with paste-ready copy per section
- Hero headline + subhead (what · for whom)
- CTA pair (Get started + Docs, or honest alternative)
- What belongs on pricing/enterprise pages instead
- 30-minute audit checklist for founder

## Done

Copy is developer-first. review and write applied to paste-ready blocks. No "contact sales" unless enterprise-only product.

## Refuse

ROI-first hero for a dev tool. Why before what. Puffery hero. Fake signup that dead-ends.
