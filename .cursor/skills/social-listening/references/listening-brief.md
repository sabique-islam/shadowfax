# Select a conversation, not an engagement count

## Query plan

Begin with one product job. For a hypothetical importer: an explicit evaluation could mention replacing an import workflow; a failed task could mention repeated preview errors; a workaround could mention splitting exports manually. These are query concepts, not claims that such posts exist today. Search the phrases actually found in customer material rather than assuming category vocabulary.

Use one or two queries per question and inspect results before expanding. Query operators differ by provider; test the operator rather than claiming it filtered results. Include the relevant language/geography and a date window chosen for the job. Search for a solved/tolerated version too: it may reveal that the problem does not justify switching.

A listing, demo feed, quoted post, or synthetic screenshot is not a live source opportunity. A search result snippet is a lead to inspect, not enough context for a personalized message. Retrieval time does not establish when a post was published.

## Qualification table

| Observed behavior | Classification | Possible next step | Unsupported leap |
| --- | --- | --- | --- |
| Asks for a replacement with concrete requirements | Explicit evaluation | Answer against actual capabilities and limitations | Assuming budget or purchase authority |
| Describes an unresolved recurring failure | Active problem | Clarify the actual task or provide a working answer | Assuming they want a new product |
| Requests the resource offered in a post | Fulfillment request | Deliver the promised artifact through the agreed route | Starting an unrelated sales sequence |
| Likes, follows, reposts, or attends | Background engagement | Inspect their own relevant work if justified | Calling them a high-intent buyer |
| Writes a vendor promotion | Seller/nonfit for this list | Exclude unless partner research is the actual task | Treating all category posts as demand |
| Praises a competitor they use successfully | Contrary evidence | Learn why the alternative works | Treating the mention as switching intent |
| Discusses a past failure now fixed | Resolved/historical | Retain only if useful for research | Presenting it as an urgent live need |

Relevance and intent are different fields. A relevant engineer can like an article for learning; a company can match firmographics while using an adequate substitute. Preserve a useful unknown instead of assigning a precise-looking intent score.

## Inspect the person and the room

Record whether the person is asking for help, answering, hiring, recruiting, promoting, or reacting. Do not transfer the author's problem to everyone who liked the post. For a competitor's post, inspect each selected person's own relevant statement; association with that competitor is not proof of dissatisfaction.

Verify identities across channels through supplied records, an original profile's own links, or other credible matching evidence. A common name, employer, or similar handle is not sufficient to merge identities. Start in the surface where they actually asked. Switching channels to evade silence or a refusal is not a qualified next step.

Check room rules and the thread's state before proposing a contribution. If an issue is already resolved or the author says no promotion, respect that. Product capability must match the problem before drafting a fix claim.

## The evidence record

Use a compact table: source URL; source published date; checked date; author/role if known; observed words; observed behavior; job fit; interpretation; missing fact; proposed next action; recheck date. Keep reposts and repeated exports deduplicated by original source and verified person/account.

If the founder supplied an engagement CSV, state what it contains and what it omits. Engagement data can seed research but cannot reveal private budgets, motives, or inbox permissions. Unknown identity/source dates stay unknown. Never fabricate missing contact details to complete the table.

## Selected sample and rejection log

Inspect a bounded set, for example ten relevant results or a one-hour research allowance, chosen as a planning limit. Return only the conversations that survive fit and source checks. Give reasons for a few rejected examples; if none qualify, say none qualify. Do not fill a quota with passive engagement.

Report the number inspected, unique origins, selected, rejected, inaccessible, stale, and unknown as appropriate. These describe this sample, not a market-wide prevalence estimate. A post count is not a lead count, and multiple interactions from one person are not independent prospects.

## Listening over time

For a requested monitoring plan, define queries, sources the host can actually access, review interval, duplicate/recheck rules, and the material change deserving attention. Do not say a watch is running until it is actually configured. If the founder explicitly requests a recurring alert, use the host's automation tools and its supported sources. No unsolicited Slack/email delivery or hidden background scraper.
